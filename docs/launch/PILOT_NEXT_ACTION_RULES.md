# Pilot Next Action Rules

## Privacy Rule

Do not commit real participant names, emails, company names, or private project details.
Use anonymized IDs such as P01, P02.
Keep the real tracker in a private location outside the repo.

## Understanding issue

If 3+ users cannot explain Cambrian after 60 seconds:

- rewrite hero copy
- simplify product intro
- avoid "runtime/harness" in public pitch
- rerun the one-minute pitch before changing product scope

## Install friction

If 2+ users fail install:

- fix install docs
- improve command output
- add install recovery note
- verify `cambrian install pack auth-bug-core` in the dry-run runner

## Pack concept confusion

If users do not understand worker pack:

- add analogy: hiring desk / 작업반
- show included workers/team/template visually
- explain that the web page selects workers and local Cambrian runs install/job/validation

## First-job friction

If users install but do not know next step:

- improve pack activate / pack next / pack start copy
- add exact next command
- keep `cambrian pack start "로그인 에러 수정해"` as the primary action

## Proof skepticism

If users ask "how do I know it worked?":

- show validation/proof step
- avoid fake public metrics
- collect real local proof after pilot
- separate canned fixture evidence from real project outcomes

## Buying signal

If user asks for own project setup:

- schedule assisted install
- record requested pack
- classify as strong signal
- ask what evidence they need before paying

## Requested pack

If 3+ users request same pack:

- consider next pack candidate
- do not build immediately unless Auth Bug Core concept is understood
- record user type and job class behind the request

## Trust concern

If a user says the product run feels overclaimed:

- inspect the exact copy or output that caused it
- remove unsupported claims
- show only local proof/outcome generated by the product run

## Messaging confusion

If users repeat the product incorrectly:

- simplify the one-liner
- remove internal terms from the first minute
- test the revised pitch with the next participant
